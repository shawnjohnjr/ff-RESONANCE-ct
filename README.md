# FINAL FANTASY RESONANCE — Cheat Engine Table

**繁體中文** | [English](README.en.md)

適用 Steam **build 24250053**。已於 macOS 標準版 CrossOver、Windows Cheat Engine 7.7 x64 測試。

## 功能

| 項目 | 功能 |
|---|---|
| 01 | 唯讀檢查目前 Gil 與背包記錄筆數 |
| 02 | 設定 Gil：0–9,999,999 |
| 03 | 唯讀背包清單：內部道具 ID 與數量 |
| 04 | 選擇已持有道具並修改數量：1–99 |
| 05 | 將目前隊伍角色升至 Lv.99，透過遊戲函式重新計算角色能力 |
| 06 | 全角色終盤裝備包：補足 8 種武器、5 種防具與 8 種飾品 |
| 07 | 自動普通攻擊：勾選持續運作，取消勾選停止 |
| 08 | 自動確認戰後結算：可獨立使用，或與第 07 項搭配 |
| 09 | 強化已持有幻兵：覺醒升滿／目前隊伍 MR 升滿，可選單隻或全部 |
| 10 | 取得幻兵：選擇單隻或補齊全部 26 隻，略過已持有 |
| 11 | 目前行動角色極限技槽補滿：一次執行，不自動放招 |
| 12 | 魔人菲娜解鎖地獄隕石：一次執行，已學會則略過 |
| 13 | 地圖移速：自動徒步 3 倍／騎乘 3.5 倍；另提供單次倍率 |

所有項目彼此獨立，預設關閉。第 01–06 項執行一次，不會凍結數值；取消勾選不會還原修改，再次執行須先取消再勾選。第 07、08 項在勾選期間持續運作，各自取消即可停止對應功能；兩項都關閉時才解除共用回呼。

第 09 項是分批執行的一次性強化；需要關閉 07、08，選擇後切回遊戲前景等待完成。取消勾選只停止剩餘項目，不會還原已完成強化。

第 10 項同樣分批執行；請先備份，關閉 07、08，並等待 09 完成。

## 使用

1. 備份自己的遊戲存檔。第 01–06 項請進入地圖並停在選單，執行期間不要戰鬥、使用道具、購物或切換地圖；第 07、08 項依下方戰鬥自動化說明操作。
2. 在遊戲所在的同一 CrossOver bottle 開啟 Windows CE，載入 [CT](FFRS_Steam_24250053_Starter.CT)。
3. 勾選「01 唯讀檢查」，對照遊戲選單。首次掃描物件需要等待，請勿重複點擊。
4. 選擇需要的功能。道具功能先選取清單項目，再輸入數量；取消則不修改。
5. 關閉再打開遊戲選單核對，確認後另存新欄位。

CT 自動連接 `FFRS-Win64-Shipping.exe`，檢查執行檔版本，從目前世界找出使用中的存檔資料。版本不符時停止，不保證適用其他更新版本。

### 道具選單

即時讀取遊戲資料表，以**英文 / 繁體中文名稱、ID、持有數量**列出目前背包內的消耗品與裝備。名稱使用本機 build 24250053 的官方 `en`／`zh-Hant` 語系，以道具 ID 精確對應，共收錄 507 組名稱（其中 2 個官方繁中欄位仍是日文，已補上標明「暫譯」的中文）；實機載入的 505 筆消耗品與裝備資料全部有雙語對應。未知 ID 顯示「Unknown item / 未翻譯道具」並保留 ID。

例如：`Potion / 治療劑`、`Phoenix Down / 鳳凰尾巴`、`Crimson Saber / 深紅烈焰`。重要道具、Artifact 與未持有道具不列入修改清單。

數量範圍 1–99 是本工具的保守限制，並非宣稱遊戲所有道具的最大堆疊量。此功能不新增道具，也不刪除背包記錄。選擇後若背包位置、筆數或原數量改變，會停止寫入。

### Lv.99

只處理目前隊伍中的主角群，不解鎖未加入角色、不修改幻兵。由各角色升級表累計至 Lv.99 所需 EXP，先以遊戲的等級計算函式核對，再呼叫 `SetPlayableUnitExperience` 更新存檔 EXP 與即時角色能力。

不需要打完一場戰鬥才生效。**目前 HP／MP 不會自動補滿**；最大 HP／MP 與能力會重新計算。已達目標經驗值的角色不重複寫入。若執行中途失敗，應檢查角色狀態；這不是跨角色的原子交易，也不會自動復原已完成角色。

### 強化已持有幻兵

第 09 項先選單一幻兵或全部已持有幻兵，再選「覺醒升滿」「目前隊伍 MR 升滿」或「兩者」。清單使用官方英文／繁體中文名稱；未知名稱仍保留 ID。

請先關閉第 07、08 項，在地圖的幻兵選單操作。確認提示後切回遊戲，保持前景且不要切換地圖、隊伍或強化幻兵；完成後會顯示結果。等待超過兩分鐘會停止。重新開啟幻兵選單核對後另存新欄位。

- 只強化已持有幻兵，不解鎖其他幻兵；MR 只修改目前隊伍角色，保留其他角色的點數。
- 上限由遊戲的 `GetMaxMasteryPoint`／`GetMaxLevel` 回報。覺醒與角色個別的精通是不同欄位；不硬套相同 MRP。已達上限時不重複寫入。
- 呼叫遊戲原本的 `SetAwakeningMasteryPoint`／`SetSynchroMasteryPoint`，逐項讀回點數與等級；不消耗魔石或 Gil。
- 檢查目前世界、存檔、持有名單、隊伍、物件生命週期與原點數；戰鬥中或資料不符時拒絕執行。修改於遊戲視窗執行緒進行，只有遊戲在前景才送出。
- 這不是整批原子交易。中途取消、失焦或錯誤時，已完成的項目會保留；檢查畫面後再決定是否存檔或重新執行。取消選擇對話框不會修改。

### 取得幻兵

第 10 項可選一隻未持有幻兵，或補齊目前版本全部 26 隻（含賽菲羅斯）。使用官方英文／繁中名稱；已持有者自動略過，原有星級與各角色 MR 保持不變。新幻兵採用遊戲初始成長，可另用第 09 項強化。

先備份存檔，關閉 07、08，等待 09 完成，停在地圖的一般選單。選擇後輸入 `YES`，切回遊戲並保持前景直到完成。重新開啟幻兵選單確認，另存新欄位。取消勾選會停止尚未執行的取得，已取得者不會還原。

- 使用此版本原生取得函式，在遊戲視窗執行緒新增紀錄；由遊戲配置幻兵陣列與八名角色的初始 MRP，不自行拼裝遊戲容器。
- 從遊戲幻兵資料表核對 26 個已知 ID；檢查版本、函式指紋、世界、存檔、戰鬥狀態及物件生命週期。每次取得後驗證持有數、既有成長、新幻兵的八組 MRP、Gil 與背包。
- 遊戲原生流程會更新收集成就，**可能立即觸發 Steam 成就**；這項影響不能靠取消勾選或讀取舊存檔撤回。
- 不會代替祠堂問答、任務或 Boss 戰劇情。未完整測試提早取得後，將來逐一完成原取得事件的影響；「名單與存檔正常」不代表全劇情相容性已驗證。

### 自動普通攻擊

第 07 項參考 MIT 授權的 [Resonance Game Boosters](https://github.com/Darjjj/resonance-game-boosters)，透過遊戲既有的選招、指令合法性檢查與選敵函式，讓輪到的我方角色執行普通攻擊。這不是重新打開被停用的原生 AutoBattle，不會使用魔法或道具；單獨啟用第 07 項時不會自動確認戰後結算。無法使用普通攻擊時會等待。

- 保持 Windows Cheat Engine 開啟並勾選第 07 項。每次重開遊戲都需要重新啟用；不會寫入存檔或安裝 ASI／DLL 模組。
- 戰鬥自動化改用管理器／視窗直接連結及類別反射；本次標準版 CrossOver 的空白快取唯讀測試約 13.5 秒備齊攻擊資料，正式 CT 約 15.2 秒開始選招。這是實測紀錄，不是固定時間保證。另一項仍在運作時，開啟第二項會共用既有連線。請保持遊戲在前景，停在一般戰鬥可選指令的畫面。
- Windows/Wine 回報遊戲失去前景、遊戲暫停或播放劇情時，不送指令。對 macOS 所有視窗切換情境的焦點回報不作保證；想確定暫停時，直接取消勾選。
- 取消勾選後不再送新指令；已確認的一次攻擊仍可能播完。若停在選敵途中，請自行取消或完成該指令，再重新啟用。
- 遊戲結束或 CE 改連其他程序時，輪詢會停止。關閉 CE 後不會再排入新指令；正在處理的一筆指令不保證能撤回。

實作使用遊戲視窗的訊息回呼，在遊戲自己的執行緒呼叫 `ProcessEvent`，不覆寫遊戲／引擎的既有程式碼。每筆呼叫有期限，且會核對目前世界、物件註冊位置、序號及指令狀態；狀態不符則跳過。停用時解除回呼，保留少量已配置記憶體至遊戲結束，避免仍在返回中的回呼讀到已釋放的程式碼。

**先前崩潰與修正：** 未發布的原型曾在回呼讀取控制資料時發生存取違規，當時尚未送出攻擊。崩潰紀錄能確認失敗位置，但不足以證明那塊資料為何變成不可讀。修正版將可讀寫資料與回呼程式碼分開配置，並在回呼中用 `VirtualQuery` 檢查控制資料及每個檢查位址後才讀取。獨立測試刻意將控制資料設為不可讀，回呼仍能安全跳過，恢復後可繼續呼叫；無效位址及不符的狀態也會拒絕執行。這項修正不是宣稱已證明 CrossOver 或 Rosetta 的底層原因。

- 直接連結不可用時，備援搜尋新指令視窗會暫時提高掃描量；每批最多 4,096 筆，每 32 筆檢查一次 20 ms 時間上限，同時從表尾回查並保留向前巡查，找到後恢復每批 256 筆。初次建立物件清單每批最多 2,048 筆。這是搜尋預算，並非保證的完成時間。
- 每 2 秒清理失效的視窗與函式；類別及繼承快取每次各檢查最多 8 筆，分批回收；辨識物件時核對位置與生命週期編號，避免沿用已被遊戲重用的位置。兩項自動功能都關閉時清空快取。主要增加的是搜尋期間的讀取與 CPU 工作，未量測實際記憶體用量。

在 `SELECT RESONANCE` 共鳴選擇畫面，第 07 項只會取消該選單並繼續普通攻擊，不會選擇共鳴招式。取消必須同時符合 Finish 指令模式、對應戰鬥階段、可見指令視窗與前景／場景檢查；只呼叫該視窗的取消函式，不送全域按鍵。

**直接定位路徑：** `GWorld → World 子系統表 → CPP_UI_BattleSubsystem → BtlWidget（核對弱指標索引與序號）→ WBP_BattleLayout_C → WBP_BtlCmdLayout_C → VM_BtlCmd`。同一子系統提供 `ResultWidget`，遊戲實例的子系統表提供整體 UI 根視窗。結算視窗可能到勝利時才建立，出現後才從其類別取得 `InputDecide`。原生函式從類別的子欄位連結取得，不再逐一搜尋所有函式物件；直接定位成功後停止掃描註冊表，連結不符時仍保留舊搜尋備援。原有的呼叫前狀態、生命週期、前景與場景檢查均保留。

第 07、08 項使用輕量唯讀連線，省去道具資料表掃描；第 01–06 項仍使用完整存檔／資料表連線。每次重開都重新取得有效指標，不保存跨程序位址或固定物件索引。首次仍需尋找原生類別，因此不是瞬間完成；以下實測範圍是此 Steam 版本與標準版 CrossOver，不代表所有場景及電腦。

實機驗證（2026-10-26）：遊戲與 CE 重開後，正式 CT 從空白戰鬥快取啟用，第 07、08 項連續完成兩場普通戰鬥，使用者均確認自動回到地圖；第二場沒有重新載入或勾選。記錄共 9 次攻擊確認、2 次共鳴取消及 14 次結算頁確認，未記錄執行錯誤。獨立測試涵蓋直接連結失效、換世界、類別函式查找與旗標、重用物件位置、分批清理、搜尋預算、共鳴取消條件及結算保護。

### 自動確認戰後結算

第 08 項是獨立開關：可以自己手動戰鬥、只讓 CT 處理結算，也可以同時勾選第 07、08 項，從普通攻擊一路自動完成結算。關掉第 08 項會保留自動攻擊；關掉第 07 項會保留自動結算。

此功能沿用 [Resonance Game Boosters](https://github.com/Darjjj/resonance-game-boosters) 的結算畫面處理方式，只呼叫目前結算元件的 `InputDecide`，以至少 250 ms 的間隔送出確認及放開事件，不送全域 Enter／鍵盤輸入。頁面動畫、數字累加、翻頁與獎勵處理仍由遊戲執行，不直接修改獎勵數值。

送出前會核對結算元件、目前頁面、結果資料模型與畫面根元件；有其他啟用中的系統／彈出視窗、遊戲暫停或劇情播放時等待。頁面已結束或回到地圖時停止確認。確認導致元件被回收時，不會把放開事件轉送到其他畫面。仍需保持 CE 開啟，且遊戲被 Windows/Wine 視為前景。

兩項共用同一個遊戲執行緒回呼，避免重複掛接。兩項都取消勾選後停止輪詢並解除回呼；已送出的那次確認可能完成，取消勾選不能撤銷已領取的正常戰鬥獎勵。此版已測一般戰鬥結算，未遍測特殊劇情戰、敗北／重試與所有獎勵頁面。

### 目前行動角色極限技槽補滿

第 11 項在一般戰鬥指令畫面，將目前輪到的我方角色極限技槽一次補至其即時上限。先關閉 07、08，輪到目標角色時勾選 11，再切回遊戲保持前景。完成後自行選擇極限技；下次需要補槽時取消再勾選。取消勾選會停止等待，但不還原已補的槽。

只補槽，不解鎖技能、不自動施放，也不凍結數值。共鳴選擇、選敵途中、敵方角色、遊戲暫停或劇情中不執行；等待兩分鐘仍沒有適合畫面會停止。沿用遊戲執行緒與物件生命週期檢查，以角色參數中的戰鬥 ID 呼叫原生補槽函式，並讀回槽量。依角色即時上限補滿；本次版本全域上限為 200（兩格）。

實機測試（2026-10-27，標準版 CrossOver）：正式腳本將當前角色從 65 補至 200，讀回成功，使用者確認畫面滿槽；魔人菲娜另從 0 補至 200，使用者確認可正常施放極限技並播放動畫。不會主動存檔，但遊戲自身的自動存檔仍可能保存遊戲狀態。

## CrossOver 啟動時提示缺少 VC++ x64

### 本次遇到的原因

在標準版 CrossOver 26.3、Steam build 24250053 的測試環境，啟動器顯示：

```text
The following component(s) are required to run this program:
Microsoft Visual C++ 2015-2022 Redistributable (x64)
```

當時 bottle 已安裝 Microsoft VC++ runtime；問題是啟動器檢查到的 DLL 版本仍不符合要求。以下為本次檢查結果，不代表所有 CrossOver 版本都相同：

| 檢查項目 | 版本 |
|---|---|
| 此遊戲啟動器要求的最低版本 | 14.42.34438 |
| CrossOver 內建的 `msvcp140_2.dll`、`vcruntime140_1.dll` | 14.42.34433.0 |
| bottle 中已安裝的 Microsoft 原生 runtime DLL | 14.51.36247.0 |

因此，只確認「已安裝 VC++」還不夠，也需要確認啟動時選用了哪一套 DLL。這次讓遊戲優先使用已安裝的 Microsoft 原生 DLL 後，順利進入著色器編譯與遊戲地圖。

### 成功使用的啟動方式

1. 正常退出其他 CrossOver 版本中的 Steam／遊戲，再用**標準版 CrossOver** 開啟遊戲所在 bottle 的 Steam 並登入。
2. 確認同一 bottle 已具備相容的 **x64** Microsoft Visual C++ v14 Redistributable。若尚未安裝，從 [Microsoft 官方下載頁](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) 取得 x64 安裝程式，透過 CrossOver 在該 bottle 執行。套件架構應配合 Windows 遊戲的 x64 架構。
3. 遊戲尚未執行時，在 macOS「終端機」使用下列命令。先按自己的安裝位置調整前三個變數；若 CrossOver 裝在系統 Applications，第一行改成 `CROSSOVER_APP="/Applications/CrossOver.app"`。

```sh
CROSSOVER_APP="$HOME/Applications/CrossOver.app"
BOTTLE_NAME="Steam"
GAME_EXE='C:\Program Files (x86)\Steam\steamapps\common\FINAL FANTASY RESONANCE\FFRS.exe'

SteamAppId=3259780 SteamGameId=3259780 \
  "$CROSSOVER_APP/Contents/SharedSupport/CrossOver/bin/wine" \
  --bottle "$BOTTLE_NAME" --no-update \
  --dll 'msvcp140,msvcp140_1,msvcp140_2,vcruntime140,vcruntime140_1=n,b' \
  --debugmsg '-all' \
  --cx-app "$GAME_EXE"
```

`n,b` 表示先嘗試 Microsoft 原生 DLL，再嘗試 CrossOver/Wine 內建實作；它不會自行安裝缺少的 runtime。`--no-update` 避免這次啟動觸發 bottle 更新。命令明確使用標準版 CrossOver 的執行檔。

此 DLL 選擇設定只作用於這次啟動及其繼承設定的子程序，沒有寫入永久的 bottle DLL 覆寫設定。下次直接按 Steam 的「開始遊戲」不一定會沿用，需要再次使用此命令。本次未重新安裝遊戲，也未修改 CrossOver MGVF 的設定。

若標準版與 MGVF 共用同一個 bottle，安裝／修復 runtime 仍會改動共用的 Windows 環境。本次 bottle 已有合適的原生 runtime，成功的關鍵是這個單次啟動的 DLL 選擇設定。以上是此 build 的實測處理方式；更新遊戲或 CrossOver 後應重新確認版本與錯誤原因。

### 後續修正：直接點 CrossOver 原本的遊戲圖示

上面的終端機命令只解決單次啟動。後續已把相同參數保存在 CrossOver 的 **FINAL FANTASY RESONANCE 共用捷徑**，不再需要每次輸入命令或另開 macOS 啟動器，也不需要 Cheat Engine。

本次原圖示指向 Windows `.url` 檔案，內容是 `steam://rungameid/3259780`，並非直接執行 `FFRS.exe`。當 Steam 已在執行時，不能依賴替網址捷徑新增的環境變數傳給既有 Steam 程序。GUI「運行命令」雖有環境變數欄位，本次最終採用 CrossOver 隨附的 `cxmenu` 工具，替換原圖示的實際啟動命令。

實際處理流程：

1. 備份 bottle 的 `cxmenu.conf`、`cxbottle.conf`，以及 Resonance 在 Windows 桌面與開始選單中的兩個 `.url` 原檔。
2. 將這兩個原檔移到掃描範圍以外的備份目錄。這可避免 CrossOver 重新掃描 Windows 捷徑時，把自訂命令覆蓋回 Steam 網址捷徑；原檔保留供還原。
3. 使用標準版安裝目錄下的 `bin/cxmenu --bottle … --create … --type raw --command … --icon … --description … --install`，更新 `cxmenu.conf` 中**原有的兩個 Resonance 項目**，保留圖示名稱與圖示。`--create` 在本次指定的是既有項目識別路徑，並非另建不同名稱的遊戲圖示。
4. 命令固定指向標準版 CrossOver 的 `bin/wine`，直接執行 `FFRS.exe`，並帶入上方相同的 `SteamAppId`、`SteamGameId`、`--no-update` 與 `--dll …=n,b` 參數。不要用會隨目前 CrossOver 版本改變的程式路徑。
5. 比對前後設定：只有 Resonance 的兩個選單項目改變，`cxbottle.conf` 位元組相同，其他遊戲（包含忍者龍劍傳 4）的捷徑未變。關閉遊戲後，從 CrossOver 原本的圖示啟動；使用者確認正常進入標題畫面，沒有 VC++ 錯誤。

**共用範圍：** 本機標準版與 MGVF 共用 Steam bottle 及選單設定，因此兩邊看到的是同一份 Resonance 捷徑。經使用者確認後，只修改這個遊戲的捷徑，固定由標準版啟動；沒有修改 MGVF 程式、圖形選項、全 bottle DLL 覆寫或其他遊戲設定。不要把這種共用捷徑修正描述成只在一個 GUI 中生效。

**日後使用：** 先讓該 bottle 的標準版 Steam 開啟並登入，再點 CrossOver 裡的 **FINAL FANTASY RESONANCE**。此修正不會替 Steam 收藏庫的「開始遊戲」按鈕加入參數。移動 CrossOver／遊戲、重建捷徑或更新後若設定改變，需重新確認儲存的命令。

**還原：** 將備份的兩個 `.url` 放回各自原位置，還原 `cxmenu.conf` 中對應的兩個項目，再用 CrossOver 的選單工具重新匯出／整理。若其間還有其他捷徑變動，不要直接覆蓋整份舊 `cxmenu.conf`。本機路徑與備份沒有放進此公開 repo。

新增功能時：在 `src/` 建立依功能命名的 Lua 檔，於 `TABLE_ENTRIES` 加入唯一 ID 與來源路徑，再執行產生器。共享的定位與資料操作邏輯放在對應輔助檔，功能檔負責操作流程與介面。產生器會拒絕重複 ID、重複來源及遺漏的來源檔案。

請修改 Lua 原始碼並重新產生 CT，避免直接編輯產生的 CT。僅整理程式碼時，可比較產生前後 CT 的 SHA-256；涉及執行邏輯變更時，再進行 CE 語法檢查與相應實機驗證。

### 地圖移速

第 13 項選擇「自動：徒步 3x／騎乘 3.5x」，保持勾選即可在上下陸行鳥時自動套用各自原速；魔導裝甲外觀同樣支援。取消勾選會停止偵測並恢復仍有效、仍由本功能控制的原速。停止再移動可刷新遊戲移動元件。

自動模式會重新辨識目前操控角色，倍率不累乘；無法自由操作或處於戰鬥時暫停套用。另保留 1／1.5／2／3 倍單次選項：1 倍恢復原速，單次模式取消勾選不還原。沒有修改全域時間、動畫速度或戰鬥倍率。

2026-10-27 標準版 CrossOver 實機確認：魔導裝甲騎乘原速 350／500／400，3.5 倍為 1225／1750／1400；使用者確認上下騎乘均正常、倍率不累加。停止功能後，徒步速度讀回 180／450／230。獨立測試另涵蓋暫停／恢復、切換與取消還原。建築物、飛空艇與戰鬥切換尚未實機驗證；飛空艇不支援。
